# Pixelated redaction drag reads the frame back once

## Engineering
- `src/overlay/annotations/DrawingLayer.tsx` reads the decoded frame back once per source canvas into a module-level `WeakMap` cache. An effect fills the cache when the frame decodes in the pixelated style. Before, each drag frame called `getImageData` for the rect (about 6 MB on a large display).
- The preview canvas is resized only when its size changes, so a move keeps one backing store.
- `forEachBlockMean` in `pixelate.ts` takes optional `stride` and `offset` arguments. The preview averages a sub-rectangle of the cached frame in place, with the block grid at the clipped rect origin, so it stays byte-identical to the bake in `annotate.ts` and `redact.rs`.
- The cost is a second copy of the decoded frame (about 59 MB on a 5K display) while the pixelated style is active.

## User value
A drag of a pixelated redaction no longer reads the screen image back on each move, so the redaction follows the pointer with less stutter. The per-frame block averaging is unchanged, so a very large redaction on a 5K display can still be slow.

## Initiative positioning
This is one of six first-wave stages of the Glitch Spot security and performance review. The other first-wave stages are hygiene, the MCP Host and Origin guard, redaction integrity, the tray redraw loop, and snapshot privacy. The share-links stage starts after redaction integrity and the tray fix merge. The frame-path stage starts last, and it removes the second frame decode that this stage left in place.
