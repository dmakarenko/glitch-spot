# v1.1-electron-sdk — Design Seed

> Part of initiative: `docs/initiatives/glitch-spot/INITIATIVE.md`

**Stage goal:** An npm SDK that embeds the Glitch Spot annotation overlay into any Electron+TypeScript+React application. A developer adds one package and four lines of main-process code; their app gains a hotkey-triggered, screenshot-backed annotation overlay that delivers structured snapshots to a callback of their choice.

**Primary use case (v1):** verified internal testers in debug/staging builds.
**Future use case:** end-user bug reporting in production builds.

---

## Scope

### In v1
- macOS only
- Frozen-mode capture only (screenshot → annotate → deliver)
- Single `mainWindow` target
- Three trigger paths: hotkey, programmatic `gs.open()` from main, optional renderer trigger via preload
- Optional floating `<GlitchSpotButton />` React component
- Single delivery mechanism: `onSnapshot(snap)` async callback
- Optional host-app metadata injected at capture time

### Out of scope for v1
- Windows / Linux
- Live mode (transparent overlay over running UI)
- Multiple window targets
- Built-in delivery adapters (webhook, clipboard) — host app owns delivery
- MCP endpoint inside the host app
- Any cloud/relay infrastructure

## Package structure

New directory added to the existing repo via npm workspaces:

```
glitch-spot/
├── packages/
│   └── electron/               @glitch-spot/electron
│       ├── src/
│       │   ├── main.ts         main-process entry point
│       │   ├── preload.ts      renderer bridge (contextBridge)
│       │   └── renderer.ts     renderer-safe exports
│       ├── overlay/            pre-built annotation UI bundle (see §Overlay UI)
│       ├── package.json
│       └── tsconfig.json
├── src/                        existing React overlay source (shared)
├── src-tauri/                  unchanged
└── package.json                add workspaces: ["packages/*"]
```

**Two entry points:**
- `@glitch-spot/electron` — main-process (Node.js). Exports `GlitchSpot`.
- `@glitch-spot/electron/renderer` — renderer-safe. Exports `GlitchSpotButton`, `glitchSpot`.

## Main process API

```typescript
import { GlitchSpot } from '@glitch-spot/electron'

const gs = GlitchSpot.init(app, mainWindow, config)

gs.open()   // programmatic trigger
gs.stop()   // unregister shortcut, destroy overlay window
```

### Config

```typescript
interface GlitchSpotConfig {
  /** Global shortcut string. Omit to disable hotkey entirely. */
  hotkey?: string

  /** Called with the completed snapshot. May be async. Errors are caught and logged. */
  onSnapshot: (snapshot: GlitchSnapshot) => void | Promise<void>

  /** Called at capture time; return value merged into snapshot.context.app.metadata. */
  metadata?: () => Record<string, unknown>
}
```

### GlitchSpotInstance

```typescript
interface GlitchSpotInstance {
  open(): void    // trigger a capture from main-process code
  stop(): void    // full teardown
}
```

### Lifecycle

`GlitchSpot.init()`:
1. Validates config (throws if `onSnapshot` is missing)
2. Registers the global shortcut if `hotkey` is set
3. Creates and loads the hidden overlay `BrowserWindow`
4. Attaches `mainWindow` event listeners: `resize`, `move`, `close`
5. Sets up IPC handlers for trigger, snapshot delivery, and cancel

## Overlay BrowserWindow

### Construction

```typescript
const overlay = new BrowserWindow({
  parent: mainWindow,
  transparent: true,
  frame: false,
  alwaysOnTop: true,
  skipTaskbar: true,
  show: false,
  webPreferences: {
    preload: path.join(__dirname, 'overlay-preload.js'),
    contextIsolation: true,
    nodeIntegration: false,
  },
})
overlay.loadFile(path.join(__dirname, 'overlay/index.html'))
```

Using `parent: mainWindow` gives automatic move/minimize/close propagation from the OS.

### Trigger flow

1. Trigger fires (hotkey / `gs.open()` / renderer IPC)
2. `mainWindow.webContents.capturePage()` → `NativeImage`
3. Overlay bounds set to match `mainWindow` content bounds
4. Image sent to overlay via IPC: `glitch-spot:frame` (base64 PNG)
5. Overlay shown and focused
6. User annotates; `Cmd+Return` to save, `Esc`+confirm to discard
7. On save: overlay sends `glitch-spot:snapshot` IPC → `onSnapshot(snap)` fires
8. On discard: overlay sends `glitch-spot:cancel` IPC
9. Overlay hidden

### Edge cases

- **Trigger while overlay is visible:** no-op; a second capture does not interrupt an in-progress annotation.
- **mainWindow resized during active session:** overlay stays locked to the captured frame size for the duration of the session.
- **mainWindow closed during active session:** overlay is destroyed as a child window; `onSnapshot` is never called.

## Renderer integration

### Preload setup

Required only if using `<GlitchSpotButton />` or `glitchSpot.open()` from renderer code.

If the host app has an existing preload:
```javascript
// existing-preload.js
const { glitchSpotPreload } = require('@glitch-spot/electron')
glitchSpotPreload()  // exposes window.glitchSpot via contextBridge
```

If the host app has no preload:
```typescript
import { preloadPath } from '@glitch-spot/electron'
new BrowserWindow({ webPreferences: { preload: preloadPath } })
```

### Floating button

```tsx
import { GlitchSpotButton } from '@glitch-spot/electron/renderer'
<GlitchSpotButton position="bottom-right" />
```

Renders nothing when `window.glitchSpot` is absent (i.e., in any build where `GlitchSpot.init()` was never called). Debug-only behaviour requires no conditional imports on the host side.

### Programmatic renderer trigger

```typescript
import { glitchSpot } from '@glitch-spot/electron/renderer'
glitchSpot.open()  // → IPC → main process trigger
```

## Snapshot schema

```typescript
interface GlitchSnapshot {
  id: string                    // "snap_<12hex>"
  created_at: string            // ISO 8601
  mode: 'frozen'
  annotations: Annotation[]
  context: {
    screen: {
      width: number
      height: number
      scale_factor: number
    }
    os: {
      platform: string
      version: string
    }
    app: {
      name: string              // Electron app.getName()
      version: string           // Electron app.getVersion()
      metadata?: Record<string, unknown>  // from config.metadata()
    }
  }
  images: {
    clean_base64: string        // base64 PNG — renderer content, no annotations
    annotated_base64: string    // base64 PNG — annotations overlaid
  }
}

interface Annotation {
  id: string
  shape: 'rect'
  coords: { x: number; y: number; w: number; h: number }
  note: string
}
```

**Key differences from the standalone schema:**
- `images` keys are `clean_base64` / `annotated_base64` (base64 strings, not file paths)
- `annotated_base64` is always present (never `null`) — if there are no annotations the clean image is used
- `context.screen.display_index` is omitted — not meaningful for a single-window capture
- `context.app` block is new

The `id` format and `Annotation` shape are intentionally identical to the standalone schema so that consumers (e.g., the Glitch Spot CC skill) can process both without branching.

## Overlay UI adaptation

The annotation UI (`src/` in the repo) currently communicates via Tauri IPC (`window.__TAURI__`). For the SDK overlay it uses a `window.glitchSpotBridge` object injected by the overlay's preload script.

**Runtime detection** (no build-time branching):
```typescript
// inside the overlay UI source
const bridge = window.__TAURI__
  ? tauriBridge()       // existing Tauri path
  : window.glitchSpotBridge  // Electron path, injected by overlay-preload.js
```

The bridge interface covers the full IPC surface between the UI and its host:
```typescript
interface OverlayBridge {
  onFrame(cb: (base64Png: string) => void): void
  onPresent(cb: (mode: 'frozen' | 'live') => void): void
  saveSnapshot(snapshot: GlitchSnapshot): void
  cancel(): void
}
```

The overlay bundle (`overlay/index.html` + assets) is built by Vite as part of the SDK package's build step — same source, same output, just with the bridge detection active.

## Error handling

- `GlitchSpot.init()` throws synchronously if `onSnapshot` is missing.
- `webContents.capturePage()` failure → overlay is not shown; error logged to console (no user-visible effect).
- `onSnapshot` errors → caught, logged; overlay hides normally.
- Hotkey registration failure (e.g. conflict) → logged as a warning; SDK continues without the shortcut.

## Distribution

- Published to npm as `@glitch-spot/electron`
- Built with `tsup` (dual CJS + ESM output)
- `overlay/` assets are included in the npm package (not in `.npmignore`)
- Peer dependencies: `electron >= 28`
- No runtime dependencies beyond Node.js built-ins and Electron APIs
