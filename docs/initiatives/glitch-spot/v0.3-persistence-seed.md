# Glitch Spot v0.3 — Persistence (Design Seed)

**Date:** 2026-05-25
**Status:** Draft — design approved, ready for implementation planning
**Part of initiative:** [`INITIATIVE.md`](./INITIATIVE.md)
**Related:** [`scope.md`](./scope.md) §12 (locked UX defaults — local snapshot retention 24h)

---

## 1. Goal

Persist Glitch Spot snapshots (clean PNG, annotated PNG, snapshot JSON) to `~/.glitch-spot/snapshots/{id}/` instead of `/tmp`, and sweep dirs older than 24h on app startup. Closes the gap between the snapshot object's `images.*` paths and a stable filesystem location the MCP skill can read back hours after capture.

## 2. On-disk layout

```
~/.glitch-spot/
  snapshots/
    snap_01HXYZABCD/
      clean.png
      annotated.png
      snapshot.json
    snap_01HXYZWXYZ/
      ...
```

- One directory per snapshot, named by snapshot id.
- `snapshot.json` is `serde_json::to_string_pretty` of the `Snapshot` struct — same shape as what's already written to the clipboard today.
- `clean.png` and `annotated.png` are the byte streams currently written to `/tmp/glitch-spot-{id}.png` and `/tmp/glitch-spot-{id}-annotated.png`.
- The snapshot's `images.clean` and `images.annotated` fields hold the absolute paths to these two files. No schema change.

## 3. Module structure

### 3.1 `snapshot/build.rs` — refactored to pure assembly

Today's `build_and_write` mixes assembly and I/O. Split: keep assembly here, move I/O to `persist.rs`. The function's ABOUTME already flagged this split as v0.3 work.

- Rename `build_and_write` → `build`.
- New return type:
  ```rust
  pub struct BuiltSnapshot {
      pub snapshot: Snapshot,
      pub clean_bytes: Vec<u8>,
      pub annotated_bytes: Vec<u8>,
  }
  ```
- `build` takes the snapshots base dir as a parameter so it can compute the final `clean.png` / `annotated.png` paths to embed in `snapshot.images.*`.
- No filesystem writes inside `build`. `BuildError` keeps only its `Annotate` variant; `Io` moves to persistence, and `NoFrame` is removed (it's dead today — the no-frame check already lives at the call site in `save_snapshot`).

Signature:
```rust
pub fn build(
    frame: &CapturedFrame,
    mode: &str,
    annotations: Vec<IncomingAnnotation>,
    os_platform: &str,
    os_version: &str,
    base_dir: &Path,
) -> Result<BuiltSnapshot, BuildError>;
```

### 3.2 `snapshot/persist.rs` — new module, owns filesystem I/O

```rust
pub const MAX_AGE: Duration = Duration::from_secs(24 * 60 * 60);

/// Returns `~/.glitch-spot/snapshots/`, creating it (and parent) if absent.
pub fn snapshots_dir() -> io::Result<PathBuf>;

/// Writes the three files to `{base}/{built.snapshot.id}/`.
/// On any per-file failure, attempts `remove_dir_all` on `{id}/` so callers
/// never see a partial directory. Propagates the original error either way.
pub fn write(base: &Path, built: &BuiltSnapshot) -> io::Result<()>;

/// Deletes immediate subdirectories of `base` whose mtime is older than
/// `max_age`. Per-entry failures are logged via `eprintln!` and skipped.
/// Returns the number of directories successfully removed.
pub fn cleanup(base: &Path, max_age: Duration) -> io::Result<usize>;
```

`HOME` resolution: `std::env::var("HOME")`. No new crate dependency; macOS-only target.

### 3.3 `snapshot/mod.rs` — re-exports

Add `pub mod persist;` and re-export `BuiltSnapshot`.

## 4. Call-site flow (`lib.rs::save_snapshot`)

```rust
let base = snapshot::persist::snapshots_dir().map_err(|e| e.to_string())?;
let built = snapshot::build::build(
    &frame, &mode, annotations, os_platform, &os_version, &base,
).map_err(|e| e.to_string())?;
snapshot::persist::write(&base, &built).map_err(|e| e.to_string())?;
let snap = built.snapshot;

state.snapshot_store.publish(snap.clone());
// existing: latest_snapshot_at update, clipboard write, overlay hide
```

The `snap.images.clean` / `snap.images.annotated` paths returned to the frontend (and embedded in clipboard JSON / surfaced via MCP) now point at `~/.glitch-spot/snapshots/{id}/...`.

## 5. Startup cleanup (`lib.rs::run`)

After spawning the MCP server, before constructing the Tauri `Builder`:

```rust
match snapshot::persist::snapshots_dir() {
    Ok(base) => {
        if let Err(e) = snapshot::persist::cleanup(&base, snapshot::persist::MAX_AGE) {
            eprintln!("[glitch-spot] cleanup failed: {e}");
        }
    }
    Err(e) => eprintln!("[glitch-spot] could not resolve snapshots dir: {e}"),
}
```

Synchronous. A scan over a handful of small dirs is sub-millisecond; failures never block startup.

## 6. Cleanup logic — age determination

Filesystem mtime via `metadata().modified()`. Not the `created_at` field inside `snapshot.json`:

- Tolerates partially-written or malformed dirs.
- Avoids per-entry JSON parsing.
- Matches the user's intuition ("files older than a day get removed").

Non-directory entries inside `base` (e.g., a stray `.DS_Store`) are ignored, not removed.

## 7. Error handling

| Failure | Behavior |
|---|---|
| `snapshots_dir()` cannot create `~/.glitch-spot/snapshots/` | `save_snapshot` returns `Err(string)` to the frontend; cleanup at startup logs and skips. |
| `write()` mid-write failure (e.g., disk full after `clean.png`) | Attempt `remove_dir_all` on the partial `{id}/`, then propagate original error. Next startup cleanup catches anything left behind. |
| `cleanup()` cannot read `base` | Returns `Err`; logged in startup wrapper, app continues. |
| `cleanup()` per-entry remove fails | `eprintln!`, continue with remaining entries. |

No `/tmp` fallback. Either the user data directory is writable or we surface the failure.

## 8. Tests

### 8.1 New: `snapshot/persist.rs` unit tests

Add `tempfile = "3"` and `filetime = "0.2"` to `src-tauri/Cargo.toml`'s `[dev-dependencies]` (verify whether `tempfile` is already declared; the v0.4 server tests may have introduced it).

1. `write_creates_directory_and_three_files` — call `write` against a tempdir, assert `{id}/clean.png`, `{id}/annotated.png`, `{id}/snapshot.json` exist with the expected bytes; assert the JSON parses back into a `Snapshot` with matching id.
2. `cleanup_removes_dir_older_than_max_age` — write a built snapshot, set its dir mtime to 25h ago via `filetime::set_file_mtime`, run `cleanup(base, MAX_AGE)`, assert dir gone and return value is 1.
3. `cleanup_keeps_dir_newer_than_max_age` — fresh write, `cleanup`, dir still present, return value 0.
4. `cleanup_returns_count_of_removed_dirs` — three backdated + one fresh, expect return value 3 and only the fresh dir remaining.
5. `cleanup_tolerates_non_directory_entries` — touch `{base}/.DS_Store`, run `cleanup`, assert the stray file is untouched and the call returns Ok.
6. `write_rolls_back_on_partial_failure` — pre-create `{base}/{id}/annotated.png` as a *directory* (so `fs::write` of the same path fails because the target is a dir); call `write`, assert it returns Err and the `{id}/` dir has been removed. (Tests the rollback contract; the exact mechanism for forcing a mid-write failure can be revisited if this proves flaky on macOS — alternative: pre-fill the disk via a `tmpfs` cap.)

### 8.2 Updated: `snapshot/build.rs` / `snapshot/tests.rs`

- Update existing `build_and_write` tests to call the new `build` with a `TempDir` base.
- Assert returned `BuiltSnapshot.snapshot.images.clean` / `images.annotated` equal `{base}/{id}/clean.png` / `{base}/{id}/annotated.png`.
- Assert `BuiltSnapshot.clean_bytes == frame.png` (or whatever the existing equality assertion checks).

### 8.3 Integration

`save_snapshot` already has end-to-end coverage via the integration tests added in v0.4. They should continue to pass once the call site is updated; no new integration test is needed in v0.3.

## 9. Out of scope

Explicit non-goals for v0.3:

- **Reading snapshots back from disk for MCP `get_snapshot(id)`.** The in-memory `SnapshotStore` remains the source of truth for what `get_snapshot` returns. Disk is write-only from the app's perspective in v0.3.
- **Migrating existing `/tmp/glitch-spot-*.png` files.** They'll be cleaned by OS `/tmp` policy.
- **Persisting `latest_snapshot_at` across app restarts.** The tray menu's "Latest snapshot: N min ago" resets on restart, as today.
- **Quota enforcement.** 24h time-based cleanup is the only pruning policy. No max-count or max-disk-size guardrails.
- **Compressing or thinning the on-disk snapshot JSON.** Pretty-printed JSON is fine at v0.3 volumes.

## 10. Risk register

- **Disk fills up mid-write.** Caught by §7; user sees error, no half-written state lingers.
- **User has no `$HOME` set.** `snapshots_dir()` returns `Err`; `save_snapshot` surfaces the error. Unlikely on macOS but explicitly handled.
- **Mtime is not monotonic across timezone / NTP jumps.** Cleanup uses `now - mtime > 24h`; a backward clock jump could spare a dir from one cleanup pass. Acceptable — the next startup catches it.
- **`remove_dir_all` race with a concurrent reader (e.g., the MCP skill mid-read of `annotated.png`).** Cleanup only runs at startup, before the MCP server begins serving requests in earnest. The skill's read is point-in-time. Real but very narrow window.
