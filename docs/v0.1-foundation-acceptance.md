### Hotkey flow (the foundation contract)
- [ ] Press `Cmd+Shift+G` from any active app. Overlay appears over the active monitor within ~500 ms.
- [ ] Overlay covers the entire monitor — no taskbar gap, no Dock peek.
- [ ] Screenshot shown in overlay matches the desktop at moment of hotkey press.
- [ ] Press `Esc`. Overlay dismisses; the previously-focused app regains focus.
- [ ] Repeat hotkey + Esc cycle at least 10 times consecutively. No crashes. No leaked windows. No duplicate overlays.

### Multi-monitor (if applicable)
- [ ] Move cursor to a second monitor; press `Cmd+Shift+G`. Overlay appears on THAT monitor with that monitor's screenshot.

### Button flow (alternative paths, exercised via debug UI)
- [ ] "Capture active monitor" button prints `Captured WxH @ Sx from display N, B bytes`.
- [ ] "Run spike (file)" button writes `/tmp/glitch-spot-spike.png` and reports the path.
- [ ] "Open overlay" button shows the overlay with the screenshot (same as hotkey).
- [ ] "Hide overlay" button hides it.

### Focus / interaction (overlay must block click-through)
- [ ] While the overlay is visible, clicking on it does NOT pass through to the app underneath.
- [ ] The overlay itself can be focused and receives the Esc keypress.

### Known limitations (informational)
- Large PNG payloads (5–10 MB at 4K Retina) take a noticeable moment to travel main → overlay due to JSON number-array encoding. Expected for v0.1.
- If `Cmd+Shift+G` is already taken by another running app, registration fails at startup with a panic. Expected for v0.1.
- "No monitor at cursor" fallback: capture falls back to display 0 silently; overlay returns an error visible in `result`. Inconsistent but unlikely to trigger.
